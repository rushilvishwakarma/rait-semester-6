### Q1. Explain the <Highlight color="yellow">three GLM components</Highlight> (random, systematic, link) and <Highlight color="yellow">how they interact</Highlight>. / Describe the <Highlight color="yellow">GLM structure</Highlight> and its component roles. / <Highlight color="yellow">List and explain the three components</Highlight> of a Generalized Linear Model (GLM) with an example. <QuestionDot color="yellow" text="IA1-QB" /> <QuestionDot color="cyan" text="MSE-QB" /> <QuestionDot color="purple" text="Asked in MSE" /> <QuestionDot color="pink" text="ESE PYQ 5 marks" /> <QuestionDot color="orange" text="Important" />


A **Generalized Linear Model (GLM)** extends linear regression so that the response variable can follow distributions **other than Normal** (e.g., binary, count data).


A GLM has **three components**:


1. **Random Component**
   The probability distribution of the output $Y$ (e.g., Normal, Bernoulli, Poisson). It must belong to the **Exponential Family** (a group of standard distributions).
   $$
   Y \sim \text{Exponential Family}
   $$


2. **Systematic Component**
   A simple formula that adds up the input variables (the linear predictor):
   $$
   \eta = \beta_0 + \beta_1 x_1 + \cdots + \beta_p x_p = X\beta
   $$


3. **Link Function**
   Connects the average value ($\mu$) to the formula ($\eta$). It ensures the predictions stay within a valid range (e.g., it prevents a probability from going above 1).


   Common link functions:
   - **Identity** ($g(\mu) = \mu$) → Linear regression
   - **Logit** ($g(\mu) = \log\frac{\mu}{1-\mu}$) → Logistic regression
   - **Log** ($g(\mu) = \log(\mu)$) → Poisson regression


**Significance:**


GLMs provide a **single framework** for modeling continuous, binary, and count data while keeping the simplicity of linear models. They are widely used in statistics, ML, and economics.


**How They Interact:**


The random component defines the distribution of $Y$ and its mean $\mu$. The link function bridges $\mu$ to the linear predictor $\eta$. The systematic component builds $\eta$ from the predictors. Together:


$$
\mathbf{X}\boldsymbol{\beta} \overset{\text{Systematic}}{\longrightarrow} \eta \overset{g^{-1}}{\longrightarrow} \mu \overset{\text{Random}}{\longrightarrow} Y
$$

### Q2. Role of the <Highlight color="yellow">canonical link function</Highlight> in <Highlight color="yellow">GLMs</Highlight>? / What are <Highlight color="yellow">link functions</Highlight> and <Highlight color="yellow">why</Highlight> are they used? / Explain link functions in GLMs with an <Highlight color="yellow">example distribution</Highlight>. <QuestionDot color="yellow" text="IA1-QB" /> <QuestionDot color="green" text="Asked in IA1" /> <QuestionDot color="orange" text="Important" />


In a **Generalized Linear Model (GLM)**, a <Highlight color="blue">**link function**</Highlight> establishes a relationship between the **expected value of the response variable** and the **linear predictor**.


Mathematically, it is defined as:
$$
g(\mu) = \eta = X\beta
$$
where $\mu = E(y)$ is the mean of the response variable.


The link function transforms $\mu$ so it can be modeled as a linear combination of inputs. This is needed because many response variables have a restricted range (e.g., probabilities must be between 0 and 1).


Different distributions need different link functions:


| Link Function | Formula | Used For |
|---|---|---|
| **Identity** | $g(\mu) = \mu$ | Linear regression (no constraint) |
| **Logit** | $g(\mu) = \log\frac{\mu}{1-\mu}$ | Logistic regression ($\mu$ between 0 and 1) |
| **Log** | $g(\mu) = \log(\mu)$ | Poisson regression ($\mu > 0$) |
| **Probit** | $g(\mu) = \Phi^{-1}(\mu)$ | Binary classification ($\mu$ between 0 and 1) |


**Why are they important?**


1. They keep predictions within the **valid range** for the response variable.
2. They let us use **one GLM framework** for many data types (binary, count, continuous).
3. The **canonical link** (default for each distribution) makes parameter estimation simpler.


Thus, link functions provide <Highlight>**flexibility**</Highlight>, ensure valid predictions, and allow linear models to handle a wide variety of response variables.

### Q3. <Highlight color="yellow">Explain Probit regression</Highlight> and <Highlight color="yellow">compare with Logistic regression</Highlight>. / Compare Probit and Logistic regression: link functions, assumptions, and scenarios. <QuestionDot color="yellow" text="IA1-QB" /> <QuestionDot color="orange" text="Important" />


**Probit regression** is a GLM used for binary classification. It models probability using the **standard normal CDF**:


$$
P(y=1 \mid x,w) = \Phi(w^T x)
$$


where:
$$
\Phi(z) = \int_{-\infty}^{z} \frac{1}{\sqrt{2\pi}} e^{-t^2/2} \, dt
$$


The link function is:
$$
g(\mu) = \Phi^{-1}(\mu)
$$


---


**Logistic regression** is also a GLM for binary classification. It models probability using the **sigmoid function**:


$$
P(y=1 \mid x,w) = \frac{1}{1 + e^{-w^T x}}
$$


The link function is:
$$
g(\mu) = \log\frac{\mu}{1-\mu}
$$



### Comparison

| Aspect        | Probit Regression         | Logistic Regression             |
| ------------- | ------------------------- | ------------------------------- |
| Link Function | Probit ($\Phi^{-1}(\mu)$) | Logit ($\log\frac{\mu}{1-\mu}$) |
| Function      | Normal CDF                | Sigmoid                         |
| Assumption    | Gaussian (normal) noise   | Logistic noise                  |


### Practical Scenarios


* **Logistic Regression**: Used for general binary classification problems due to simplicity
* **Probit Regression**: Used when the underlying latent variable is assumed to be normally distributed

### Q4. What is <Highlight color="yellow">multitask learning</Highlight>? How does <Highlight color="yellow">parameter sharing</Highlight> enhance generalization with <Highlight color="yellow">scarce data</Highlight>? / <Highlight color="yellow">Explain the concept of multitask learning</Highlight> in GLMs. <QuestionDot color="yellow" text="IA1-QB" /> <QuestionDot color="green" text="Asked in IA1" /> <QuestionDot color="pink" text="ESE PYQ 5 marks" />


**Multitask Learning (MTL)** trains multiple related tasks **together** in a single model instead of building separate models for each task.

The core idea is <Highlight>**parameter sharing**</Highlight>, which has two types:

1. **Hard Sharing**: Tasks share the same hidden layers, only output layers are separate. Most common and reduces overfitting.
2. **Soft Sharing**: Each task has its own model, but parameters are pushed to stay similar.

**How Parameter Sharing Helps:**

1. **Knowledge Transfer**: Tasks with less data learn from tasks with more data
2. **Regularization**: Shared parameters reduce overfitting, especially for low-data tasks
3. **Better Features**: Model learns general patterns useful across all tasks
4. **Handles Scarce Data**: Low-data tasks borrow strength from high-data tasks via shared prior
5. **Better Generalization**: Leads to more stable estimates and improved performance across tasks

**Examples:**

- **NLP**: One model doing NER + POS tagging + sentiment analysis together.
- **Vision**: One model doing object detection + segmentation + depth estimation.
- **Healthcare**: Predicting readmission, mortality, and stay length from the same patient data.

**Significance:**

MTL is more data-efficient and produces more robust models than single-task learning, especially when individual tasks have limited labeled data.



**Real-World Examples:**
- Speech recognition across multiple languages
- Medical diagnosis of multiple related diseases
- NLP: sentiment analysis + emotion detection trained together

### Q1. What are <Highlight color="yellow">Directed Graphical Models (Bayesian Networks)</Highlight>? Explain <Highlight color="yellow">causal relationships</Highlight> and <Highlight color="yellow">probabilistic inference</Highlight>. / Define DGMs and how they represent joint probability. <QuestionDot color="yellow" text="IA1-QB" /> <QuestionDot color="cyan" text="MSE-QB" /> <QuestionDot color="purple" text="Asked in MSE" /> <QuestionDot color="orange" text="Important" />


**Directed Graphical Models (DGMs)** are probabilistic models that use a **directed graph** to show dependencies between random variables. Each **node** = a variable, each **arrow** = a dependency.


A **Bayesian Network** is a DGM whose graph is a **DAG (Directed Acyclic Graph)** — no cycles.


**Graphical Structure:**


Represented as a **Directed Acyclic Graph (DAG)** where nodes are random variables and directed edges (arrows) encode direct dependencies. No cycles are allowed.


**Joint Probability Factorization:**


$$
P(X_1, X_2, \dots, X_n) = \prod_{i=1}^{n} P(X_i \mid \text{Parents}(X_i))
$$


**Real-World Example — Medical Diagnosis (Flu):**


- Flu (Y) causes Fever ($X_1$), Cough ($X_2$), Fatigue ($X_3$)

**DAG:**

<Mermaid chart={`graph TD
  Y[Flu] --> X1[Fever]
  Y --> X2[Cough]
  Y --> X3[Fatigue]
`} />


$$
P(Y, X_1, X_2, X_3) = P(Y) \cdot P(X_1 \mid Y) \cdot P(X_2 \mid Y) \cdot P(X_3 \mid Y)
$$


**How It Facilitates Inference:**


- If a patient has Fever and Cough, we can compute $P(Y=1 \mid X_1=1, X_2=1)$ using Bayes' theorem.
- The graph structure tells us **which variables are relevant** — reducing computation.

$$
\text{Full Joint: } 2^4 - 1 = 15 \text{ parameters}
$$

$$
\text{DAG (Bayesian Network) Factorization: } 7 \text{ parameters}
$$


**Markov Property:**


A node is **conditionally independent of all non-descendants given its parents**.

---
**The Markov Property (Family Tree Analogy):** Once you know the **parents'** DNA, knowing the **ancestors'** (grandparents) DNA provides no extra information.

### **CPTs and Noisy-OR**
*   **CPT**: A giant table listing every possible combination of causes for an effect (e.g., having Flu AND a Cold).
*   **The Problem**: With many causes, this table becomes **too big to manage** (grows exponentially as $2^n$).
*   **The Solution (Noisy-OR)**: Instead of the giant table, we list the chance for each cause **separately**. This shrinks the table size from $2^n$ down to just $n$.


### Q2. How do Bayesian Networks use <Highlight color="yellow">conditional independence</Highlight>? Explain <Highlight color="yellow">two properties</Highlight> with examples. / Explain conditional independence in DGMs with <Highlight color="yellow">graphical intuition</Highlight>. / What is <Highlight color="yellow">d-separation</Highlight> in Directed Graphical Models? Explain with a simple example. / <Highlight color="yellow">List and explain any two conditional independence properties</Highlight> of Directed Graphical Models. <QuestionDot color="yellow" text="IA1-QB" /> <QuestionDot color="cyan" text="MSE-QB" /> <QuestionDot color="purple" text="Asked in MSE" /> <QuestionDot color="pink" text="ESE PYQ 5 marks" /> <QuestionDot color="orange" text="Important" />


**Conditional independence** means two variables don't affect each other once we know a third variable:


$$
P(X, Y \mid Z) = P(X \mid Z) \cdot P(Y \mid Z) \quad \Leftrightarrow \quad X \perp Y \mid Z
$$


In Bayesian Networks, the graph structure directly encodes conditional independencies. We use **d-separation** to check: if all paths between two nodes are "blocked" by observed variables, they are conditionally independent.


**Three Basic Structures:**


**1. Chain (Serial Connection):** $A \to B \to C$


- $A \perp C \mid B$
- Observing $B$ **blocks** the path from $A$ to $C$.
- Example: Smoking → Tar deposits → Cancer. If we know about tar deposits, smoking gives no additional info about cancer.


**2. Fork (Common Cause):** $B \leftarrow A \to C$


- $B \perp C \mid A$
- Observing common cause $A$ **blocks** the path from $B$ to $C$.
- Example: Season → Rain, Season → Sprinkler. Knowing the season makes rain and sprinkler independent.


**3. Collider (Common Effect):** $A \to B \leftarrow C$


- $A \perp C$ (marginally independent), but **NOT** $A \perp C \mid B$
- Observing $B$ **opens** the path (explaining away effect).
- Example: Intelligence → Grades ← Study Hours. Knowing grades creates a dependency between intelligence and study hours.

### Q5. What is a <Highlight color="yellow">Directed Gaussian Graphical Model (DGGM)</Highlight>? Explain the <Highlight color="yellow">Gaussian distribution assumption</Highlight>.


A **Directed Gaussian Graphical Model (DGGM)** is a Bayesian Network where all variables are continuous and follow a **Gaussian distribution**. The conditional distributions are **linear Gaussian**, meaning each variable is a simple linear formula of its parents plus some noise.

### Q1. <Highlight color="yellow">Derive MLE</Highlight> for <Highlight color="yellow">mean and variance</Highlight> of a univariate <Highlight color="yellow">Gaussian distribution</Highlight>. <QuestionDot color="orange" text="Important" />

Given $y_1, \dots, y_N \sim \mathcal{N}(\mu, \sigma^2)$.

**Log-likelihood:**
$$
\ell = -\frac{N}{2}\log(\sigma^2) - \frac{1}{2\sigma^2}\sum (y_i - \mu)^2
$$

---

### For $\mu$

$$
\frac{\partial \ell}{\partial \mu} = \frac{1}{\sigma^2}\sum (y_i - \mu) = 0
$$
$$
\Rightarrow \hat{\mu} = \frac{1}{N}\sum y_i
$$

---

### For $\sigma^2$

$$
\frac{\partial \ell}{\partial \sigma^2} = 0
$$
$$
\Rightarrow \hat{\sigma}^2 = \frac{1}{N}\sum (y_i - \mu)^2
$$

### Q2. What is a <Highlight color="yellow">Gaussian Mixture Model (GMM)</Highlight>? Write its <Highlight color="yellow">PDF / Mathematical expression</Highlight> (K components). / For <Highlight color="yellow">customer purchase amounts</Highlight>, analyze suitability of <Highlight color="yellow">Gaussian, Poisson, or Binomial</Highlight>. <QuestionDot color="cyan" text="MSE-QB" /> <QuestionDot color="purple" text="Asked in MSE" /> <QuestionDot color="orange" text="Important" />

A **Gaussian Mixture Model (GMM)** represents data as a **combination of multiple Gaussian (normal) distributions**. It is used for **soft clustering**.

### 1. Mathematical Expression (PDF)
For a mixture model with $K$ components, the probability of $x$ is:
$$ p(x) = \sum_{k=1}^{K} \pi_k \mathcal{N}(x \mid \mu_k, \Sigma_k) $$

Where:
*   **$K$**: Number of components (clusters).
*   **$\pi_k$**: Mixing coefficient ($\sum \pi_k = 1$).
*   **$\mu_k, \Sigma_k$**: Mean and Covariance of each Gaussian.
*   **$z$**: **Latent (hidden) variable** indicating the component.

### 2. Analysis: Customer Purchase Amounts
For modeling purchase amounts (continuous data), we analyze:
*   **Gaussian (Suitable)**: Best for continuous data. A GMM can model spender groups (e.g., small vs. large spenders).
*   **Poisson (Not Suitable)**: Used for discrete **count data** (e.g., number of items), not monetary amounts.
*   **Binomial (Not Suitable)**: Used for **binary (yes/no)** outcomes.


### Q3. Steps of the <Highlight color="yellow">EM algorithm</Highlight> and why they are crucial for <Highlight color="yellow">parameter estimation</Highlight>. / Explain <Highlight color="yellow">E-step and M-step</Highlight> and why it <Highlight color="yellow">guarantees convergence</Highlight>. / What are the <Highlight color="yellow">two main steps</Highlight> in the EM algorithm? Illustrate them briefly. / Explain the use of the EM algorithm for <Highlight color="yellow">clustering using Gaussian Mixture Models (GMMs)</Highlight>. / <Highlight color="yellow">Outline the steps</Highlight> involved in the EM algorithm. / With an example, demonstrate how <Highlight color="yellow">EM algorithm is used to fit a GMM</Highlight>. <QuestionDot color="cyan" text="MSE-QB" /> <QuestionDot color="purple" text="Asked in MSE" /> <QuestionDot color="pink" text="ESE PYQ 5 marks" /> <QuestionDot color="red" text="ESE PYQ 10 marks" /> <QuestionDot color="orange" text="Important" />

The **Expectation-Maximization (EM) Algorithm** is an iterative method for maximum likelihood estimation when data has **latent (hidden) variables**.

---

### E-step (Expectation)

$$
\gamma_{nk} = \frac{\pi_k \mathcal{N}(x_n|\mu_k,\Sigma_k)}{\sum_{j=1}^K \pi_j \mathcal{N}(x_n|\mu_j,\Sigma_j)}
$$

---

### M-step (Maximization)

$$
N_k = \sum_n \gamma_{nk}
$$

$$
\mu_k = \frac{1}{N_k}\sum_n \gamma_{nk} x_n
$$

$$
\Sigma_k = \frac{1}{N_k}\sum_n \gamma_{nk}(x_n - \mu_k)(x_n - \mu_k)^T
$$

$$
\pi_k = \frac{N_k}{N}
$$

---

### **Why EM is Needed:**
*   **Hidden Labels**: While MLE is easy if labels are known, optimization becomes difficult when labels are **latent (missing)**.
*   **Iterative Process**: EM solves this by alternating between estimating labels (**E-step**) and optimizing parameters (**M-step**).

### **Convergence:**
*   **Guaranteed Increase**: The log-likelihood is mathematically designed to **increase** at every iteration.
*   **Local Optimum**: Since the likelihood is bounded, the algorithm always converges to a **local optimum**.

### Q6. <Highlight color="yellow">Compare GLMs and GLMMs</Highlight>: model structure, <Highlight color="yellow">random effects</Highlight>, and application scenarios. <QuestionDot color="orange" text="Important" />

**Generalized Linear Models (GLMs)** model the expected value of $Y$ using only fixed predictors: $g(E[Y|X]) = X\beta$.

**Generalized Linear Mixed Models (GLMMs)** extend GLMs by adding **random effects** $b$ to account for group-level variation: $g(E[Y|X,b]) = X\beta + Zb$, where $b \sim \mathcal{N}(0, \Psi)$.

| Generalized Linear Model (GLM) | Generalized Linear Mixed Model (GLMM) |
|-------------------------------|-----------------------------------------|
| Models expected value using only **Fixed Predictors**. | Models expected value using both **Fixed and Random effects**. |
| Assumes **Independent Observations**. | Handles **Grouped, Clustered, or Repeated** data. |
| Estimation is done via **MLE** (analytical). | Estimation is done via **MLE or REML** (numerical). |
| Focuses on **Population-level** inference. | Allows for **Subject-level** inference. |
| Best for **Independent samples**. | Best for **Hierarchical or Longitudinal** data. |

### **When to Use GLMMs:**
*   **Hierarchical Data**: Students nested in schools (where schools are random effects).
*   **Repeated Measures**: Multiple tests performed on the same patient over time.
*   **Grouped Data**: Any scenario where observations are **non-independent** due to grouping.

# Module 4 — Markov Chains & Hidden Markov Models


### Q1. <Highlight color="yellow">Markov property</Highlight> (1st order). For <Highlight color="yellow">2nd order</Highlight>, write probability expression and draw dependency <Highlight color="yellow">diagram</Highlight>. <QuestionDot color="orange" text="Important" />

**First-Order Markov Property:**

The future state depends only on the **current state**, not on any earlier history:
$$
P(x_t \mid x_{t-1}, x_{t-2}, \dots, x_1) = P(x_t \mid x_{t-1})
$$

Joint probability of a sequence factorizes as:
$$
P(x_1, x_2, \dots, x_T) = P(x_1) \prod_{t=2}^{T} P(x_t \mid x_{t-1})
$$

**Diagram (First-Order):**
<Mermaid chart={`graph LR
  x1 --> x2
  x2 --> x3
  x3 --> x4
  x4 --> x5["..."]
`} />

**Second-Order Markov Chain:**

The current state depends on the **last two states**: $P(x_t \mid x_{t-1}, x_{t-2}, \dots) = P(x_t \mid x_{t-1}, x_{t-2})$

Joint probability:
$$
P(x_1, \dots, x_T) = P(x_1) \cdot P(x_2 \mid x_1) \cdot \prod_{t=3}^{T} P(x_t \mid x_{t-1}, x_{t-2})
$$

**Diagram (Second-Order):**
<Mermaid chart={`graph LR
  x1 --> x3
  x2 --> x3
  x2 --> x4
  x3 --> x4
  x3 --> x5
  x4 --> x5
`} />
Each node $x_t$ has **two parents**: $x_{t-1}$ and $x_{t-2}$.

**Limitation:** Higher-order models increase parameters exponentially. HMMs are preferred as they capture long-range dependencies through a latent first-order chain.

### Q2. Define <Highlight color="yellow">transition and emission probabilities</Highlight> in <Highlight color="yellow">HMMs</Highlight> and their significance. <QuestionDot color="pink" text="ESE PYQ 5 marks" />

An HMM is defined by three parameters $(A, B, \pi)$, which act as the "rules" of the model:

---

### **1. Transition Probabilities (A)**
The chance of moving from one **hidden state** to another.
*   **Formula**: $a_{ij} = P(q_{t+1} = S_j \mid q_t = S_i)$
*   **Example**: If you are **Healthy** today, what is the chance you will be **Sick** tomorrow?

### **2. Emission Probabilities (B)**
The chance of seeing a specific **observation** given a hidden state.
*   **Formula**: $b_j(k) = P(O_t = v_k \mid q_t = S_j)$
*   **Example**: If you are **Sick** (hidden), what is the chance you will have a **Fever** (observation)?

### **3. Initial Probabilities ($\pi$)**
The chance of being in a specific state at the very **start** (time $t=1$).
*   **Example**: What is the chance that a patient is **Healthy** when they first walk into the clinic?

**Significance:**
- **Transitions** show how the system **evolves over time**.
- **Emissions** connect the **hidden world to the data we can see**.
- **Initial states** set the **starting point** for the model.

---

### **Key Idea**

* **Transition** → state to state
* **Emission** → state to observation

---

### **Example (intuition)**

* Hidden state = Weather (Rainy/Sunny)
* Observation = Activity (Walk, Shop)
* Transition → Rainy → Sunny
* Emission → Rainy → more likely “Shop”

### Q3. Three <Highlight color="yellow">fundamental problems of HMMs</Highlight> and their <Highlight color="yellow">algorithms</Highlight>. / <Highlight color="yellow">Describe how inference is performed</Highlight> in Hidden Markov Models. <QuestionDot color="pink" text="ESE PYQ 5 marks" /> <QuestionDot color="orange" text="Important" />

**1. Evaluation (Likelihood)**

* **Description:** Compute the probability that the model generates the observation sequence
  $$
  P(O|\lambda)
  $$
* **Algorithm:** Forward Algorithm


**2. Decoding (Most Likely State Sequence)**

* **Description:** Find the most likely hidden state sequence for the observations
  $$
  \arg\max_Q P(Q|O,\lambda)
  $$
* **Algorithm:** Viterbi Algorithm


**3. Learning (Parameter Estimation)**

* **Description:** Estimate model parameters from observed data
  $$
  \lambda = (A, B, \pi)
  $$
* **Algorithm:** Baum-Welch Algorithm (EM)

### Q4. <Highlight color="yellow">Forward variable</Highlight> $\alpha_t(i)$ for HMM. Provide <Highlight color="yellow">steps of Forward Algorithm</Highlight> with math expressions. / What is <Highlight color="yellow">filtering</Highlight> in Hidden Markov Models? How is it performed? / How do you perform filtering (<Highlight color="yellow">forward algorithm</Highlight>) in a Hidden Markov Model? Write the basic recursion. <QuestionDot color="pink" text="ESE PYQ 5 marks" /> <QuestionDot color="red" text="ESE PYQ 10 marks" /> <QuestionDot color="orange" text="Important" />

**Forward Variable:** $\alpha_t(i)$ = probability of observing the first $t$ symbols AND being in state $S_i$ at time $t$.

**Algorithm Steps:**

**Initialization** ($t = 1$):
$$
\alpha_1(i) = \pi_i \cdot b_i(O_1)
$$
- $\pi_i$: probability of starting in state $S_i$; $b_i(O_1)$: emission probability

**Recursion** ($t = 2, 3, \dots, T$):
$$
\alpha_t(j) = \left[\sum_{i=1}^{N} \alpha_{t-1}(i) \cdot a_{ij}\right] \cdot b_j(O_t)
$$
- Sum over all previous states, then multiply by the emission probability at time $t$

**Termination:**
$$
P(O \mid \lambda) = \sum_{i=1}^{N} \alpha_T(i)
$$
- Sum forward probabilities at the final time step over all states.

**Trick to remember (Forward Algorithm):**

* **Start:** initial × emission
* **Loop:** sum(previous × transition) × emission
* **End:** sum all


### Q5. A person's health condition has two hidden states: <Highlight color="yellow">Healthy (H) and Sick (S)</Highlight>. Initial probabilities: $\Pi=[0.6, 0.4]$. Transition matrix $A=[[0.7,0.3],[0.4,0.6]]$. Observations: <Highlight color="yellow">Normal (N), Fever (F)</Highlight>. Emission matrix $B=[[0.8,0.2],[0.3,0.7]]$. Find the probability of observation sequence <Highlight color="yellow">$O=(\text{Normal, Fever})$</Highlight>. <QuestionDot color="red" text="ESE PYQ 10 marks" />

The probability of the observation sequence $O = (\text{Normal, Fever})$ is found using the **Forward Algorithm**:
$$ \alpha_t(j) = \left[ \sum_i \alpha_{t-1}(i) \cdot a_{ij} \right] \cdot b_j(o_t) $$

**Calculation:**

**1. For the first observation: Normal (N)**
- $\alpha_1(H) = \pi_H \cdot b_H(N) = 0.6 \times 0.8 = \mathbf{0.48}$
- $\alpha_1(S) = \pi_S \cdot b_S(N) = 0.4 \times 0.3 = \mathbf{0.12}$

**2. For the second observation: Fever (F)**
- $\alpha_2(H) = [\alpha_1(H) a_{HH} + \alpha_1(S) a_{SH}] \cdot b_H(F)$
  $$ = [(0.48)(0.7) + (0.12)(0.4)] \times (0.2) = 0.384 \times 0.2 = \mathbf{0.0768} $$
- $\alpha_2(S) = [\alpha_1(H) a_{HS} + \alpha_1(S) a_{SS}] \cdot b_S(F)$
  $$ = [(0.48)(0.3) + (0.12)(0.6)] \times (0.7) = 0.216 \times (0.7) = \mathbf{0.1512} $$

**3. Final Probability:**
Add the final forward probabilities:
$$ P(O = (N, F)) = \alpha_2(H) + \alpha_2(S) = 0.0768 + 0.1512 = \mathbf{0.228} $$

**Answer:** The probability of the observation sequence is **0.228**.

# Module 5 — Undirected Graphical Models


### Q1. Apply <Highlight color="yellow">conditional independence</Highlight> to <Highlight color="yellow">undirected graphical models</Highlight> (MRF) using chain A-B-C. <QuestionDot color="orange" text="Important" />


**Markov Random Fields (MRFs)** encode conditional independence through **graph separation**: two variables are conditionally independent if removing a set of observed nodes disconnects their paths.


**Chain Structure: A — B — C**


**Joint Probability Factorization:**


Using the **Hammersley-Clifford theorem**, the joint distribution factorizes over **maximal cliques**. In a chain, the maximal cliques are $\{A, B\}$ and $\{B, C\}$:


$$
P(A, B, C) = \frac{1}{Z} \psi_{AB}(A, B) \cdot \psi_{BC}(B, C)
$$


where:
- $\psi_{AB}(A, B)$ = potential function over clique $\{A, B\}$ — captures compatibility between A and B
- $\psi_{BC}(B, C)$ = potential function over clique $\{B, C\}$
- $Z = \sum_{A,B,C} \psi_{AB}(A,B) \cdot \psi_{BC}(B,C)$ = partition function (normalization constant)


**Conditional Independence Property:**


In the chain A — B — C:
- **Pairwise:** A and C are not directly connected → $A \perp C \mid \{B, \text{all others}\}$
- **Global (Graph Separation):** Node B separates A from C → $A \perp C \mid B$


$$
P(A, C \mid B) = P(A \mid B) \cdot P(C \mid B)
$$


This is the **global Markov property**: once B is observed, A and C become independent — B "blocks" all information flow between them.

### Q2. Explain <Highlight color="yellow">Conditional Random Fields (CRFs)</Highlight>, draw diagram, and explain <Highlight color="yellow">node/edge factors</Highlight>. <QuestionDot color="orange" text="Important" />

A **Conditional Random Field (CRF)** is an undirected probabilistic graphical model that directly models $P(Y \mid X)$ — the conditional distribution of output labels $Y$ given observed input $X$.

**Linear-Chain CRF Diagram:**
<Mermaid chart={`graph TD
  X1 --- Y1
  X2 --- Y2
  X3 --- Y3
  X4 --- Y4
  Y1 --- Y2
  Y2 --- Y3
  Y3 --- Y4
`} />

**Formula:**
$$
P(Y \mid X) = \frac{1}{Z(X)} \prod_{t=1}^{T} \phi_{\text{node}}(Y_t, X, t) \cdot \prod_{t=1}^{T-1} \phi_{\text{edge}}(Y_t, Y_{t+1}, X, t)
$$
*(where $Z(X)$ is the normalization constant)*

**1. Node Factors (Unary Potentials) $\phi_{\text{node}}$:**
*   **Tells how well one label fits one input word.**
*   Example: In NER, they help decide if "New" is a location label.

**2. Edge Factors (Pairwise Potentials) $\phi_{\text{edge}}$:**
*   **Tells how likely two neighboring labels are to go together.**
*   Example: It helps the model know that if one word is a **First Name**, the next word is more likely to be a **Last Name** than a **City Name**.

**Key advantage:** CRFs can use the **whole sentence (global context)**, not just nearby words.

---

### **Why CRFs Are Used in Sequence Modeling:**
*   **Discriminative**: They model $P(Y \mid X)$ directly.
*   **Flexible**: They can use many input features at once.
*   **Robust**: They avoid the **label bias problem**.
*   **Versatile**: Work well for tasks like **POS tagging, NER, and chunking**.

Both HMMs and CRFs are used for sequence labeling (e.g., POS tagging, Named Entity Recognition), but they differ fundamentally in their modeling philosophy.


| Hidden Markov Model (HMM) | Conditional Random Field (CRF) |
|---------------------------|--------------------------------|
| **Generative** model (models $P(X, Y)$). | **Discriminative** model (models $P(Y \mid X)$). |

**Example — Name Entity Recognition:**
- HMM must model $P(\text{"Barack"} \mid \text{Person})$ — the probability of a word given a tag.
- CRF can use features like: is the word capitalized? does it appear in a list of names? what are the surrounding words? — far more expressive.

### Q4. <Highlight color="yellow">Define and write formula</Highlight> for <Highlight color="yellow">Markov Random Fields</Highlight>. / What is the <Highlight color="yellow">local Markov property</Highlight> in Markov Random Fields? Explain briefly with an illustration. / <Highlight color="yellow">State and explain any two conditional independence properties</Highlight> in Markov Random Fields. <QuestionDot color="pink" text="ESE PYQ 5 marks" /> <QuestionDot color="orange" text="Important" />

A **Markov Random Field (MRF)**, also called an **Undirected Graphical Model (UGM)**, represents the joint distribution of random variables using an **undirected graph** $G = (V, E)$.

- **Nodes** $V$: random variables
- **Edges** $E$: undirected symmetric dependencies
- **No edge** = conditional independence

**Mathematical Formula:**

The joint distribution factorizes over **maximal cliques** $\mathcal{C}$:
$$
P(X_1, \dots, X_n) = \frac{1}{Z} \prod_{C \in \mathcal{C}} \psi_C(X_C)
$$

where $\psi_C(X_C) \ge 0$ = **potential function**.

**Three Markov Properties:**

| Property | Meaning |
|----------|---------|
| **Pairwise** | If no edge between $i$ and $j$, then $X_i \perp X_j$ given all others |
| **Local** | A node only depends on its neighbors. Once you know the neighbors, all other nodes don’t matter for that node. |
| **Global** | If $S$ separates $A$ from $B$ in the graph, then $A \perp B \mid S$ |

# Module 6 — Monte Carlo Inference


### Q1. What is <Highlight color="yellow">Monte Carlo Inference</Highlight> and <Highlight color="yellow">why</Highlight> is it used? <QuestionDot color="orange" text="Important" />

**Monte Carlo Inference** uses **random sampling** to approximate answers to probability questions that are too hard to solve analytically (e.g., computing expectations or marginals over complex distributions).

**Core Idea:**

Instead of solving $\mathbb{E}_p[f(x)]$ mathematically, draw $N$ random samples $x_i \sim p(x)$ and average:
$$
\mathbb{E}_p[f(x)] \approx \frac{1}{N} \sum_{i=1}^{N} f(x_i)
$$
As $N$ grows, this converges to the true answer (Law of Large Numbers).

### **Why Monte Carlo Methods are Used:**
*   **Intractable Integrals**: When posterior distributions have no **closed-form (simple, exact formula)**.
*   **Complex Distributions**: When normalizing constants (**partition functions**) are too hard to compute exactly.
*   **Latent Variables**: When summing over all **latent (hidden)** configurations is too expensive.

**Key Advantages**:
*   Works well in **High Dimensions**.
*   Provides estimates for **Expectations, Marginals, and Intervals**.
*   **Simple & Flexible**: Can be applied to almost any complex probabilistic model.

**Common Methods**: Rejection Sampling, Importance Sampling, MCMC (Metropolis-Hastings, Gibbs Sampling).


---


### Q2. <Highlight color="yellow">Rejection Sampling</Highlight> for complex distributions: requirements for <Highlight color="yellow">proposal and envelope</Highlight>. / <Highlight color="yellow">Define rejection sampling</Highlight>. Give one practical scenario where it would be used. / <Highlight color="yellow">Describe the concept of rejection sampling</Highlight>. Give one use case. <QuestionDot color="pink" text="ESE PYQ 5 marks" /> <QuestionDot color="orange" text="Important" />

**Rejection Sampling** generates independent samples from a target distribution $p(x)$ when direct sampling is impractical.

**Algorithm:**

1. Choose a **proposal distribution** $q(x)$ that is easy to sample from.
2. Find a constant $M$ such that $p(x) \le M \cdot q(x)$ for all $x$ (the **envelope condition**).
3. Repeat:
   - Draw $x^* \sim q(x)$ and $u \sim \text{Uniform}(0, 1)$
   - **Accept** $x^*$ if $u \le \frac{p(x^*)}{M \cdot q(x^*)}$; otherwise **reject** and try again.
4. Accepted samples follow $p(x)$.

**Geometric Intuition:** Think of drawing points under the envelope $M \cdot q(x)$. Accept only those that fall under $p(x)$.

### **Key Requirements:**
*   **Proposal $q(x)$**: Distribution must be easy to sample from.
*   **Coverage**: $q(x) > 0$ wherever target $p(x) > 0$ (must cover the whole support).
*   **Envelope**: There must be a constant $M$ such that $M \cdot q(x) \ge p(x)$ for all $x$.
*   **Tightness**: $M$ should be as small as possible to maximize the **acceptance rate**.

**Practical Limitation:** In high dimensions, acceptance rate drops exponentially. MCMC methods are preferred instead.

### Q3. Practical <Highlight color="yellow">challenges</Highlight> of <Highlight color="yellow">Metropolis-Hastings algorithm</Highlight>. / What is <Highlight color="yellow">Metropolis-Hastings algorithm</Highlight>? Explain its basic working. <QuestionDot color="pink" text="ESE PYQ 5 marks" />

The **Metropolis-Hastings (MH) Algorithm** builds a Markov chain whose stationary distribution is the target $\pi(x)$:

1. Propose: $x^* \sim q(x^* \mid x_t)$
2. Accept with probability: $\alpha = \min\left(1, \frac{\pi(x^*) q(x_t \mid x^*)}{\pi(x_t) q(x^* \mid x_t)}\right)$; else keep $x_t$.

### **Practical Challenges:**
*   **Burn-In Period**: Early samples are biased by the starting point and must be discarded (non-trivial to decide how many).
*   **Slow Mixing**: The chain may get "stuck" in one region (especially in multimodal distributions), leading to poor coverage.
*   **High Autocorrelation**: Consecutive samples are highly correlated; the number of truly independent samples is much lower than the total drawn.
*   **High Dimensionality**: Proposing "good" moves is extremely difficult in high dimensions.
*   **Convergence Diagnosis**: No definitive test exists; we rely on heuristics like **Visual plots and statistical checks**.



### **Comparison: Rejection vs. Importance Sampling**

| Rejection Sampling | Importance Sampling |
|-------------------|---------------------|
| Used to **generate actual samples** from a hard distribution. | Used to **calculate an average (expectation)** without generating samples. |
| Rejects "bad" samples that don't fit under the envelope. | Keeps all samples but **weights** them based on their importance. |
| Hard to find a good "envelope" $M$ in high dimensions. | Hard to find a good "proposal" $q(x)$ that matches the target. |
| **Example**: Generating random points on a map. | **Example**: Calculating the average height of people in a room. |

where $M$ is a constant such that:
$p(x) \le M q(x), \ \forall x$

**Algorithm:**

1. Sample $x^* \sim q(x)$
2. Sample $u \sim U(0,1)$
3. Accept $x^*$ if
   $u \le \frac{p(x^*)}{M q(x^*)}$

**Output:**
Produces **true i.i.d. samples from $p(x)$**.


## **Importance Sampling**

Importance Sampling is used to **estimate expectations** of the form:
$E_p[f(x)]$

when sampling directly from $p(x)$ is difficult.

Samples are drawn from $q(x)$ and assigned weights:
$w(x) = \frac{p(x)}{q(x)}$

The estimate is:
$\hat{\mu}*{IS} = \frac{\sum*{i} f(x_i), w(x_i)}{\sum_{i} w(x_i)}, \quad x_i \sim q(x)$

**Condition:**
$q(x) > 0$ wherever $p(x) > 0$

**Output:**
Gives a **weighted estimate**, not actual samples.
