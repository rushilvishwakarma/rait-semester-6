### Q1. What is Big Data? Discuss different sources that generate big data. / What is Big data? Explain types of Big data. <QuestionDot color="yellow" text="Part of MSE-QB as well" />

Big Data refers to extremely large and complex datasets that are generated at a very high speed and cannot be efficiently processed using traditional data processing systems such as relational databases. As digital technologies have advanced, data is being produced continuously from multiple sources, making it difficult for conventional systems to store, manage, and analyze it effectively.

The data becomes “Big Data” when its **size**, **speed of generation**, or **complexity** exceeds the capacity of traditional systems. Earlier systems were designed to handle structured data in limited volumes, whereas Big Data includes structured, semi-structured, and unstructured data such as text, images, videos, and sensor data. This data is generated from online transactions, social media platforms, mobile devices, scientific experiments, and IoT sensors.

Big Data plays a crucial role in modern organizations because it enables advanced analytics and data-driven decision-making. By analyzing Big Data, organizations can identify hidden patterns, predict trends, and gain deeper insights into customer behavior and business operations.

Thus, Big Data is not only about handling large volumes of data, but also about extracting meaningful value from it using specialized tools and technologies.

**Sources of Big Data:**

Big Data is generated from a wide range of sources in today’s interconnected digital environment. One major source of Big Data is **banking and credit card transactions**, where millions of financial records are generated every second. These transactions include payments, transfers, and online purchases.

Another significant source is **social media platforms** such as Twitter, Facebook, and Instagram. These platforms generate enormous amounts of unstructured data in the form of posts, comments, images, and videos. **Web and e-commerce systems** also contribute heavily by recording user clicks, searches, browsing behavior, and purchase histories.

Additionally, **mobile devices**, **sensor technologies**, and <Highlight color="blue">**Internet of Things (IoT) networks**</Highlight> generate continuous streams of real-time data. Scientific instruments and research experiments also produce large datasets that require Big Data processing techniques.

Therefore, the variety and volume of data sources contribute to the rapid growth of Big Data across industries.

### Q2. How much data does it take to be called Big Data? With example explain various data measures.

In Big Data analytics, data is measured using hierarchical storage units that represent increasing volumes of data. The smallest unit of data is a **bit**, and eight bits together form one **byte**. As data volume increases, larger units are used to represent it efficiently.

One kilobyte (KB) is equal to 1024 bytes, while one megabyte (MB) consists of 1024 kilobytes. Similarly, one gigabyte (GB) equals 1024 megabytes and one terabyte (TB) equals 1024 gigabytes. In Big Data environments, data is commonly measured in much larger units such as <Highlight color="blue">**petabytes (PB)**, **exabytes (EB)**, **zettabytes (ZB)**, and **yottabytes (YB)**</Highlight>.

Modern applications such as social media platforms, cloud services, and scientific research generate data at petabyte and exabyte scales. Traditional data processing systems struggle to handle such massive volumes, which is why Big Data technologies are required.

Hence, understanding data size units is essential to appreciate the scale and challenges associated with Big Data.

### Q3. With example explain types of Big Data. / What is Big data? Explain types of Big data. <QuestionDot color="yellow" text="Part of MSE-QB as well" />

Big Data is broadly classified into three categories based on its structure and organization, namely <Highlight>**structured data**, **unstructured data**, and **semi-structured data**</Highlight>. This classification helps in understanding how data is stored, processed, and analyzed.

**Structured data** refers to data that follows a fixed schema and is organized in rows and columns. It is usually stored in relational database management systems and can be easily queried using SQL. Examples of structured data include employee records, banking transactions, and inventory databases. Although structured data is easy to manage, handling it becomes challenging when the data size grows to extremely large volumes.

**Unstructured data** does not have a predefined format or schema. It includes data such as text documents, emails, images, videos, audio files, and system logs. This type of data constitutes the majority of Big Data generated today. Traditional databases are not well suited to store or analyze unstructured data, making it a major challenge for organizations.

**Semi-structured data** lies between structured and unstructured data. It does not follow rigid relational schemas but contains tags or markers to organize data elements. Common examples include XML and JSON files, which are widely used in web applications.

Thus, Big Data systems must be capable of handling all three types of data efficiently.

### Q5. Compare big data with traditional data. / Differentiate traditional data and big data. <QuestionDot color="yellow" text="Part of MSE-QB as well" />

Traditional data systems are designed to handle **small to moderate volumes of structured data** stored in centralized relational databases. These systems rely on fixed schemas and <Highlight color="blue">vertical scaling</Highlight> using powerful servers. They are mainly used for transactional processing and routine business operations.

In contrast, Big Data systems are designed to handle **very large volumes of structured, semi-structured, and unstructured data**. They use <Highlight>**distributed storage systems such as HDFS**</Highlight> and support horizontal scaling by adding more machines. Big Data systems operate on clusters of commodity hardware and are optimized for large-scale data analysis rather than simple transactions.

Traditional systems are limited in scalability and flexibility, whereas Big Data systems provide high scalability, fault tolerance, and cost effectiveness. Therefore, Big Data systems are better suited for modern analytics-driven applications.

### Q9. What is Hadoop? Explain Hadoop’s core components. / Explain architecture of Hadoop. / Explain Core components of Hadoop. <QuestionDot color="yellow" text="Part of MSE-QB as well" />

Hadoop is an <Highlight>**open-source framework**</Highlight> developed by the Apache Software Foundation for the <Highlight>**distributed storage and processing of large datasets**</Highlight>. It was created by *Doug Cutting* and *Mike Cafarella* in 2005 to address the challenges posed by rapidly growing data volumes.

**Core Components:**

Hadoop consists of four core components that work together to support distributed data processing. <Highlight>**Hadoop Common**</Highlight> provides shared utilities and libraries required by other Hadoop modules.

<Highlight>**HDFS (Hadoop Distributed File System)**</Highlight> is responsible for distributed storage. It splits large files into blocks and replicates them across multiple nodes to ensure fault tolerance. The <Highlight color="blue">**NameNode**</Highlight> manages metadata, while <Highlight color="blue">**DataNodes**</Highlight> store the actual data.

<Highlight>**YARN (Yet Another Resource Negotiator)**</Highlight> manages cluster resources and schedules jobs by allocating CPU and memory efficiently. <Highlight>**MapReduce**</Highlight> is the programming model used for distributed processing, where data is processed using Map and Reduce phases.

### Q11. What is HDFS? How files are written and read in HDFS?

**HDFS (Hadoop Distributed File System)** is a scalable, fault-tolerant, distributed storage system designed to run on commodity hardware.

**Write Mechanism:**
1.  Client requests NameNode to create a file.
2.  NameNode checks permissions and returns a list of DataNodes to store the first block.
3.  Client writes data packet to the first DataNode.
4.  DataNodes replicate the packet to the next DataNodes in the pipeline (Pipeline Replication).
5.  Once all replicas are written, an acknowledgment is sent back to the client.

**Read Mechanism:**
1.  Client requests NameNode for the location of a file.
2.  NameNode returns the list of DataNodes holding the blocks of the file.
3.  Client reads blocks directly from the closest DataNode (Rack Awareness).
4.  Client assembles the blocks to form the original file.

HDFS is a distributed file system designed to store large datasets across multiple nodes in a Hadoop cluster. It divides files into <Highlight color="blue">fixed-size blocks</Highlight> and distributes them across DataNodes. Each block is <Highlight>replicated, typically three times</Highlight>, to ensure fault tolerance.

### Q13. Discuss role of NameNode, Secondary NameNode, DataNode, JobTracker, TaskTracker.

**HDFS Components:**
-   **NameNode**: The "brain" of the cluster. Manages metadata (fsimage, edit logs). If NameNode goes down, the entire file system is inaccessible.
-   **DataNode**: The "worker". Stores raw data blocks. Handles I/O operations.
-   **Secondary NameNode**: Housekeeping node. Checkpoints the file system metadata to prevent the edit log from growing too large.

**MapReduce Components (Classic/MRv1):**
-   **JobTracker** (Master):
    -   Accepts jobs from clients.
    -   Assigns tasks (Map and Reduce) to TaskTrackers.
    -   Monitors task progress and re-schedules failed tasks.
-   **TaskTracker** (Slave):
    -   Runs on DataNodes.
    -   Executes the actual Map and Reduce tasks assigned by the JobTracker.
    -   Sends heartbeat signals to JobTracker to report health and progress.

### Q14. Explain concept of MapReduce using an example. Write MapReduce pseudo-code for “Group by” “Aggregations” in a database. / What is MapReduce ? Explain How Map and Reduce Work? What is Shuffling in MapReduce? / What are various types of relational algebra operations. Explain any four using Mapreduce. / Explain the various stages of Map Reduce with an example. <QuestionDot color="green" text="Asked in IA1" /> <QuestionDot color="yellow" text="Part of MSE-QB as well" />

**MapReduce Concept**
MapReduce is a programming model for processing large data sets with a parallel, distributed algorithm on a cluster.
-   **Map Phase**: Takes specific input and transforms it into key/value pairs (`<k1, v1> → list(<k2, v2>)`).
-   **Shuffle/Sort Phase**: Groups all strictly logical values by key.
-   **Reduce Phase**: Takes those grouped key/value pairs and aggregates/summarizes them (`<k2, list(v2)> → <k3, v3>`).

**Example: Group By & Aggregation**
*Scenario*: Given a dataset of `Sales(Store, Amount)`, calculate Total Sales per Store. (SQL: `SELECT Store, SUM(Amount) FROM Sales GROUP BY Store`)

**Pseudo-code:**

```python
class Mapper:
    method Map(docid, record):
        # record: "StoreA, 100"
        Store, Amount = parse(record)
        Emit(Store, Amount) 
        # Output: <StoreA, 100>, <StoreB, 200>, <StoreA, 150>

class Reducer:
    method Reduce(Store, list_of_amounts):
        # input: <StoreA, [100, 150]>
        total_sales = 0
        for amount in list_of_amounts:
            total_sales += amount
        Emit(Store, total_sales)
        # Output: <StoreA, 250>
```

### Q16. Explain mapreduce algorithm for matrix multiplication. / Write a Map reduce pseudo code matrix-vector multiplication. / Explain Matrix Vector Multiplication algorithm by MapReduce with an example. <QuestionDot color="green" text="Asked in IA1" /> <QuestionDot color="yellow" text="Part of MSE-QB as well" />

Matrix Multiplication $C = A \times B$. If matrix $A$ is size $L \times M$ and $B$ is $M \times N$.
$C_{ij} = \sum_{k=1}^{M} A_{ik} \times B_{kj}$.

**One-Step Approach (Common):**

**Map Function:**
The Mapper reads matrix elements.
-   If element is from Matrix **A** $(i, k, value)$:
    It is needed for every cell in row $i$ of the result matrix $C$.
    For each $j$ from $1$ to $N$:
    **Emit** `key=(i, j), value=('A', k, value)`
-   If element is from Matrix **B** $(k, j, value)$:
    It is needed for every cell in column $j$ of the result matrix $C$.
    For each $i$ from $1$ to $L$:
    **Emit** `key=(i, j), value=('B', k, value)`

**Reduce Function:**
The Reducer receives all values for a specific cell $(i, j)$ in the result matrix.
Input: `key=(i,j), list_of_values=[('A', 1, vA1), ('B', 1, vB1), ('A', 2, vA2)...]`
-   Initialize `sum = 0`
-   Group values by index $k$.
-   For each $k$, find $A_{ik}$ and $B_{kj}$. If both exist, multiply them ($A_{ik} \times B_{kj}$) and add to `sum`.
-   **Emit** `key=(i, j), value=sum`

### Q18. Explain limitations of Hadoop.

1.  **Latency**: Hadoop is designed for batch processing (high throughput). It is **not suitable for low-latency** or real-time queries (solved by Spark/Flink).
2.  **Small Files Problem**: HDFS is inefficient at handling millions of tiny files because the NameNode must keep metadata for every file in memory, creating a bottleneck.
3.  **Iterative Processing**: MapReduce writes intermediate results to disk after every job. This makes iterative algorithms (like Machine Learning / K-Means) very slow compared to in-memory engines like Spark.
4.  **Security**: Hadoop's default security model is weak (originally assumed trusted environment). Kerberos is needed for strong authentication, which is complex to manage.
5.  **Complexity**: Managing a Hadoop cluster requires significant operational expertise (tuning YARN, HDFS, JVMs).

### Q19. Construct Stepwise MapReduce algorithm for word count application using simple text dataset. <QuestionDot color="yellow" text="Part of MSE-QB as well" />

**Dataset**:
`File 1`: "Apple Banana"
`File 2`: "Apple Orange"

**Step 1: Input Splits**
The framework splits input files.
-   Split 1: "Apple Banana"
-   Split 2: "Apple Orange"

**Step 2: Mapping**
Mapper processes each line and emits `<word, 1>`.
-   Mapper 1 (Split 1): 
    -   Emit `<Apple, 1>`
    -   Emit `<Banana, 1>`
-   Mapper 2 (Split 2):
    -   Emit `<Apple, 1>`
    -   Emit `<Orange, 1>`

**Step 3: Shuffling and Sorting**
The framework groups values by key.
-   Key: **Apple** -> List: `[1, 1]`
-   Key: **Banana** -> List: `[1]`
-   Key: **Orange** -> List: `[1]`

**Step 4: Reducing**
Reducer sums the counts for each key.
-   Reducer(Apple, [1, 1]) -> `sum = 1+1 = 2`. Emit `<Apple, 2>`
-   Reducer(Banana, [1]) -> `sum = 1`. Emit `<Banana, 1>`
-   Reducer(Orange, [1]) -> `sum = 1`. Emit `<Orange, 1>`

**Step 5: Output**
Final result written to HDFS:
```
Apple   2
Banana  1
Orange  1
```

### Q11. Explain Google File System.

The <Highlight>**Google File System (GFS)**</Highlight> is a proprietary distributed file system developed by Google to provide efficient, reliable access to large volumes of data using clusters of commodity hardware. It was designed to handle files that are several terabytes in size and optimized for large sequential reads and data appends.

GFS operates on a **Master-Slave architecture**, where a single Master node manages all metadata, while multiple ChunkServers store the actual data. Files are divided into **fixed-size chunks (64MB)**, and each chunk is replicated across at least three ChunkServers to ensure reliability and fault tolerance in the event of hardware failure.

The design of GFS focuses on **High Throughput** rather than low latency, making it suitable for data-intensive processing tasks like web indexing. It also assumes that hardware failure is the norm rather than the exception, and thus includes robust automated recovery mechanisms.

Hence, GFS provided the architectural blueprint for the **Hadoop Distributed File System (HDFS)** and remains a milestone in the development of distributed storage systems.
